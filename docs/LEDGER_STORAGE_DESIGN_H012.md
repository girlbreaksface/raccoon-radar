## 2. Proposed entities and invariants
First implementation: manually entered USD long standard single-leg options only, explicit multiplier100. Include multiplier/deliverable identity in schema but block unsupported/unknown/adjusted/cash-settled/nonstandard deliverables rather than assuming100. No short positions, assignment/exercise accounting, FX, rebates, broker imports or tax-lot claims. Contract entry is a user assertion; no provider verification. Symbols are labels, not contract/order selection.

|Entity|Proposed persisted fields / constraints|
|---|---|
|ledger_meta|store_uuid, application marker, schema_version, accounting_policy_version, created_at_utc, reporting_timezone, price_scale, currency, creator software; immutable versioned changes only|
|contract|contract_uuid, raw option symbol, normalized underlying, expiration date, strike integer units, CALL/PUT, currencyUSD, explicit multiplier100, deliverable STANDARD_100; identity immutable; unique complete normalized identity including symbol/terms; conflicting symbol/terms rejected|
|position|position_uuid, contract_uuid FK, manual label; one long open-to-flat cycle. Subsequent new entry after flat uses new position. Status is projected, never inferred from expiration/quotes|
|fill_revision|revision_uuid, logical_fill_uuid, position_uuid FK, revision_number, supersedes_revision_uuid, action RECORD/REPLACE/VOID, side BUY_TO_OPEN/SELL_TO_CLOSE/MANUAL_ZERO_CLOSE, quantity, premium_units, fee_cents, effective_at_utc, entered local datetime, IANA zone, offset and fold, explicit tie_sequence, recorded_at_utc, monotonic recorded_sequence, reason, source_type MANUAL, client idempotency key, payload hash/policy version|
|command_receipt|unique client idempotency UUID, canonical request hash, committed revision IDs, recorded_sequence range; transactional with append; permits safe retry after lost UI acknowledgement|

No persisted editable realized-P&L/status column in first version. Derived lots, exit allocations, remaining quantities, status and summaries computed from the pinned active revision set. Caches, if later needed, are rebuildable and keyed by revision/policy; never authoritative over records. SQL FKs, NOT NULL/unique/check constraints plus application validation. No cascading deletes; source rows not updated/deleted. Contract corrections affecting existing fills create a new identity and explicit position/fill supersession batch or stop for a separately reviewed capability; never mutate contract terms in place.

REPLACE is a full validated new revision linked to the current revision; VOID is a tombstone retaining original content/reason. One successor per revision, increasing revision numbers, same logical fill, no cycles. A correction changing lots requires recomputing the whole position and all affected reporting periods before commit. A stale revision target rejects with conflict, not last-write-wins. Revisions are appended only with reason and actual recordedUTC; never backdated recorded time. Preserve previous values and original hypotheses/calculator references separately.

## 3. Exact amounts, ticks and fee allocation
Store premium/strike as nonnegative SQLite INTEGER USD units with scale100000000 (8 decimal places), quantities as positive whole integers, fees as nonnegative INTEGER USD cents. Preserve original validated decimal text for audit. Reject excess precision/nonfinite/scientific or malformed values; do not truncate floats. Entry premium>0, exit>=0. Zero close needs explicit MANUAL_ZERO_CLOSE reason/effective time, remains labeled manually asserted zero closure, not an exchange fill or automatically detected expiry.

Proposed safe bounds aligned with H011: premium/strike<=1000000, per-fill/open position quantity<=100000, fee<=100000000USD; owner must approve. Single stored amount fits signed64-bit. Compute products/sums/P&L in Python arbitrary-precision integers or isolated Decimal, NEVER SQLite REAL or unchecked SQL SUM/product. Price*quantity*multiplier may exceed64-bit despite valid individual fields. Do not persist an overflowing derived integer; export canonical exact decimal strings. Every projection checks invariants and input caps before output.

Manual fills preserve exact entered valid price, including off-reference-tick values. H011's user-selected reference tick is NOT verified exchange authority. Store optional user tick and source/status UNKNOWN/USER_ASSERTED/VERIFIED (latter requires independent evidence and scope); flag off-tick/unknown, do not silently round actual fills or present a manual tick as verified. Rounded calculator references may be linked as a separate frozen reference snapshot; they never replace entry/exit prices. A proposed exchange-rule rejection gate requires later approval/evidence.

FIFO proposal, not tax accounting: sort active fills by effectiveUTC then explicit manual tie_sequence. Require disambiguation for equal effective times; never infer execution order from UUID or retrieval order. Each exit consumes only earlier/equal-ordered open lots in the same position/contract, oldest first. Reject oversell, out-of-order negative inventory at ANY prefix, cross-contract matching and implicit shorts. Each opening partial fill is a separate lot, not a silently averaged price. Match exit partial fills separately; corrections trigger the same deterministic replay. A new buy after flat must use a new position ID under this initial policy.

For a lot of Q contracts and opening fee F cents, cumulative entry fee recognized after C closed contracts is floor(F*C/Q). A fragment's fee is the difference from the prior cumulative value. For an exit fill of Q contracts/F cents, allocate across its FIFO fragments with the same cumulative-difference rule. Final fragment receives the conserved remainder automatically; total allocated fees exactly equals each recorded fee, remainder stays with open contracts. No per-fragment proportional floating-point rounding. Example3contracts/1cent opening fee: recognized portions0,0,1cent as contracts close. Rule is explicit and versioned; do not switch silently to nearest-cent allocation.

Fragment gross USD units=(exit_price_units-entry_price_units)*multiplier*matched_qty. Net subtracts (allocated_entry_fee_cents+allocated_exit_fee_cents)*1000000. Exact8-decimal USD P&L retained in projection/export. Report dollars ROUND_HALF_UP to cents ONLY after exact aggregation; per-exit display also cents. Summaries include rounding_difference_cents when sum of displayed exit rows differs from rounded exact total. Fees are total fill dollars, not per-contract unless explicitly converted with original unit provenance. Opening fee on remaining contracts is unrecognized for realized P&L; cash-flow/debit view shows all paid fees separately. No unrealized P&L without a manually entered, explicitly dated mark and separately approved design.

## 4. Times, availability and reports
Require timezone-aware effective fill times. Preserve entered local text, zone, offset/fold and normalizedUTC; reject nonexistent DST local times and require explicit ambiguity choice. RecordedUTC is computer-clock time, with source/clock caveat; not verified broker receipt or historical availability. Stable recorded_sequence is ordering authority for as-recorded snapshots even if wall clock moves backward. Expiration is a contract date, not a closure timestamp.

Snapshot projection accepts recorded_sequence cutoff R; choose latest linked revision visible by R, discard voided fills, then match by effective ordering. Support report label as-recorded-R versus restated-current. A later correction to an older effective date changes a NEW restated report, never overwrites an earlier export. No reconstruction of unknown historical knowledge times. Policy/software/hash/timezone version included in every report.

Realized summary basis: exact net amounts allocated to EXIT effective date in approved reporting zone (recommend America/New_York), not entry date or recording date. Daily=local civil date; weekly=ISO week Monday-start with ISO year; monthly=local calendar year-month. These are civil-time periods, NOT asserted exchange sessions. Closed exit allocation count, exit-fill count, closed-position count, partial/open quantities, fee recognition, gross/net, manual-zero closes, excluded/invalid rows and missing records reported separately. Open positions are excluded from realized totals, not silently valued at zero. No win-rate/profitability/strategy inference from incomplete manual journal.

## 5. Connection and transaction boundary
Future implementation uses one owning worker/connection for writes, explicit connection close in finally/contextlib.closing, no Tk calls from workers. Read reports use an explicit read transaction to obtain a single snapshot; no connection borrowed from research modules. PRAGMA foreign_keys=ON must be set/verified per connection outside a transaction; not assumed from schema alone. SQLite documents multiple readers but a single writer; BEGIN IMMEDIATE reserves a write or can return BUSY. Sources: [transactions](https://www.sqlite.org/lang_transaction.html), [foreign keys](https://www.sqlite.org/foreignkeys.html). This informs a proposed design, not an executed concurrency test.

Save flow: canonicalize command and allocate stable client UUID before submission; BEGIN IMMEDIATE; inspect receipt; identical key/hash returns prior result, mismatched hash rejects. Re-read current revision/position, validate full proposed projection and ordering, append revisions+receipt atomically, COMMIT, then acknowledge UI. Error ->explicit rollback/close, no partial fill/receipt. Lost acknowledgement ->retry SAME key, never create a duplicate. BUSY uses bounded timeout/retry with visible state, not infinite background retries. Correction batches are all-or-nothing; invalidating later exits blocks entire batch with affected IDs, no silent cascading voids.

Recommend first version local single-writer, journal_mode=DELETE and synchronous=FULL, verified configuration; no unreviewed WAL/network/cloud assumptions. Durability still depends on OS/storage, not a guarantee against every power loss. Two application instances produce conflict/visible busy behavior, not simultaneous mutable cached state. Disable duplicate Save while pending, retain command until acknowledged. Closing UI waits/cancels queued-but-unstarted commands; never terminate an in-flight transaction and report success. Reopen reads committed receipts and full projection; no phantom pending fill created from form state.

No runtime SQL from user data, parameterize values, no loadable extensions/SQL file functions/ATTACH/VACUUM INTO in general journal command API. Trusted backup adapter alone receives explicit validated source/destination. Connection policy is NOT a general filesystem sandbox and cannot defend arbitrary Python/native code or an OS attacker. Review path aliases, permissions and file identities explicitly.

## 6. Versioning, backup and recovery
New store creation requires explicit owner action and exclusive path reservation, magic/application marker, store UUID and schema/policy version. Initialization is atomic; interrupted init leaves an unmistakably incomplete NEW file, not an existing research file repurposed. Marker is identity assistance, not authentication; validate tables/constraints/UUID/version and registry before writes. Open existing store with mode=rw only after authorized identity checks; never mode=rwc on missing Open path. Read-only diagnostics use explicit mode=ro and no initialize function.

First version has no automatic migrations. Unknown/newer version ->blocked/read-only error; older versions require separately approved migration plan, verified restorable backup and exclusive journal ownership. Each change records source/target schema, application/policy revisions, checksum, UTC and status. Never migrate/copy back over any research DB or silently replace original Ledger. Preserve original file and evidence on failure; disable writes, offer explicit recovery workflow.

Recommend SQLite online backup API to a NEW exclusively reserved destination, not raw copy of a possibly live database. SQLite backup replaces destination content, so destination boundary/exclusive creation is mandatory; it supplies a consistent snapshot, not an authorization mechanism. Source: [official backup API](https://www.sqlite.org/backup.html). Complete backup, close handles, verify integrity/FKs/ledger UUID/schema and projection at cutoff, hash and mark complete manifest last. Incomplete backups remain clearly labeled and cannot be auto-restored. Verify restores only into another new path, compare exact records/projections before owner chooses active file. No restore over a source file. Include journal sidecars/lifecycle in future crash tests; do not delete an apparently stale journal without SQLite recovery review.

Disk full, permission failure, corruption, invalid schema or missing ledger fail visibly with no overwrite/reinitialization. Preserve evidence/file, never repair in place automatically. Backups have unique UTC+UUID names, hash manifests and owner-selected local retention; no automatic deletion. Hash chains/canonical event hashes can detect accidental change and support external anchoring, but a local DB owner can rewrite both data/hashes; not tamper-proof or signed broker evidence.

## 7. Non-destructive CSV proposal
Explicit export from one pinned read transaction/recorded_sequence, never implicit export on view. New collision-resistant UTC+UUID directory/files using exclusive creation; no overwrite dialogs that replace previous exports. Produce fills/revisions.csv and realized_allocations.csv, optional periods.csv, plus manifest. Write to reserved names, close/verify hashes/counts then manifest.complete marker last; failure leaves incomplete bundle, never published complete. No promise of atomicity across multiple files; directory marker defines completion.

Fields include store/snapshot/policy IDs, revision/logical fill/contract/position IDs, raw/normalized labels, option terms/multiplier, BUY/SELL/manual-zero kind, quantities/matched lots, exact premium/fees/gross/net values, recognized fee amounts, effectiveUTC, local zone/offset/fold, recordedUTC/sequence, correction links/reason, completeness and exclusions. Include exact8-decimal USD strings and separate2dp display values; no locale-dependent comma amounts. ISO8601 UTC timestamps with Z, explicit reporting zone and ISO-week convention. Export audit revisions separately from active-as-of view so superseded values are never confused with effective fills. Filenames/hash manifest/code commit/software/Python/SQLite/tzdata versions and chosen time/fee/rounding policies recorded.

CSV text formula protection for labels/symbols/notes: escape dangerous leading formula prefixes including whitespace/control variants, quote cells, record sanitizer version. Preserve exact original text in DB; optionally an explicitly requested local JSON audit sidecar for lossless text. Sanitized CSV is not a byte-exact raw-text archive. No arbitrary user filenames, SQL or executable formulas. Manifest hash is integrity evidence, not encryption or identity proof.

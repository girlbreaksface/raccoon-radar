## Manual API / CLI
All paths must be absolute; NEW directory's parent must already exist. Existing files/directories are never replaced. No filesystem path inferred from contract/user note data.

- Ledger.create(new_directory, synthetic=True): creates a new private-mode directory and new ledger.sqlite3 plus ledger-identity.json only after initialization succeeds. Failure preserves incomplete NEW artifact, no automatic reinitialization.
- Ledger.open(existing_directory, readonly=False): existing recognized synthetic store only. Open on missing/foreign/version-mismatched path never creates/migrates it. readonly=True rejects apply. Backups can only be opened read-only.
- apply(command_uuid, fills): one atomic committed batch sequence, max100 revisions. Client must retain command UUID and exact request across retries. Identical key/payload returns committed receipt; changed payload rejects. Commands/fill revisions/positions are append-only, protected against UPDATE/DELETE by triggers. No independent database authenticity guarantee.
- report(sequence=None): one read-transaction snapshot; cutoff is a committed command sequence (0 for empty), never an inside-batch ordinal. Includes immutable source command requests/hashes, all revisions up to cutoff, active fills, positions, FIFO allocations and Eastern daily/ISO-week/month summaries. Corrections produce a new restatement; requesting the old sequence reproduces the old report.
- export(new_directory, sequence=None): exclusive revisions.csv, allocations.csv, periods.csv, exact report.json and final manifest.json with hashes/count-independent schema/policy/software/tzdata/checkout-source hash context. Manifest exists only after all payload files close/fsync. No multi-file atomicity claim. Failures leave incomplete bundle. Text formula prefixes escaped; generated negative exact numeric columns remain numeric text. JSON preserves original command field values in canonical JSON, not source-file spacing or formatting.
- backup(new_directory): SQLite backup API consistent image, integrity/FK/identity verified, read-only BACKUP marker/hash written last. Hash mismatch rejects restore.
- Ledger.restore(backup_directory, new_directory, synthetic=True): new path only, source backup unchanged; logical ledger UUID/records retained, physical file identity rebound. It is a restored branch of history; owner must not use divergent copies as a synchronized multi-device ledger.
- Ledger.recover(existing_directory, confirm_exclusive=True): explicit sole-owner assertion, creation file identity/marker required. Raw database/marker/journal captured exclusively first as RAW_CAPTURE_NOT_VERIFIED_BACKUP, not represented as a restorable consistent backup. SQLite alone performs rollback/finalization on known owned store; code never manually deletes a journal. A cold nonzero journal is finalized by a same-version header transaction. WAL recovery blocked. No unattended recovery or corruption repair/migration.

CLI equivalents: create DIRECTORY --synthetic; template ABSOLUTE_REQUEST_FILE; record DIRECTORY ABSOLUTE_REQUEST_FILE; report DIRECTORY --sequence N; export DIRECTORY NEW_DESTINATION --sequence N; backup DIRECTORY NEW_DESTINATION; restore BACKUP NEW_DESTINATION --synthetic; recover DIRECTORY --confirm-exclusive. Prefix with python manual_ledger_cli.py. Template writes an exclusive fictional example JSON file; edit it manually, do not use it as a contract selector. Record does not place a trade. Duplicate JSON keys/nonfinite JSON rejected. CLI errors return2 without tracebacks or fill-detail logs. No operation overwrites an existing destination; no automatic data deletion/retention task.

## Request and accounting contract
Request envelope has exactly command_id and fills. Each normal fill supplies fill_id,revision_id,expected_revision (null for new),position_id,complete synthetic contract,side,quantity,premium,fees,effective_at (explicit offset),timezone (America/New_York or UTC),tie,reason,tick,tick_authority and synthetic=true. Use template for exact spelling. Replace uses same fill_id/position/contract plus new revision_id and exact current expected_revision. Void is a minimal command containing fill_id,revision_id,expected_revision,void=true,reason,synthetic=true; no silently ignored replacement terms. One logical fill revision per batch. Contract terms cannot change in place; conflicting symbol/terms rejected. Contract-level correction/migration capability remains excluded.

Premium/strike decimal strings converted exactly to integer USD units1e-8; fill fees are total fill USD cents. Whole quantities1..100000; premium/strike<=1000000, fees<=100000000USD, notes<=4096, batches<=100 and total revisions<=10000 (draft resource limits). No floats/SQL aggregate arithmetic. Products beyond signed64-bit handled in Python integers. Entry and SELL_TO_CLOSE premiums positive. Zero exit requires explicit MANUAL_ZERO_CLOSE and reason, never inferred from expiry or price. Unknown/off-reference tick flags preserve actual entered price; no exchange-rule claim, no silent rounding.

FIFO by effectiveUTC then explicit tie sequence; ambiguous equal-time ties, any negative inventory prefix, oversell and new cycle after flat in same position reject whole batch. Each opening fill is a lot. Cumulative floor allocation F*C/Q conserves every entry/exit fee cent; open lot retains unrecognized entry fee. Net exact USD=(exit-entry)*100*matched quantity -recognized entry/exit fees. Output exact8dp, HALF_UP2dp display; period totals sum exact units before rounding and report display-row rounding residual. Partial exits recognize P&L on EXIT Eastern civil date; weekly uses ISO week/year, monthly uses local calendar month. Open positions unmarked; no unrealized P&L or profitability/strategy metrics. Missing periods are not invented exchange sessions.

Example: buy3 at1.00/entryfee0.01, sell1 at1.20/exitfee0.01 =>19.99; sell2 at0.90/fee0.01 =>-20.02, net-0.03. Correct original entry to1.05 =>new restated-15.03, original sequence remains-0.03. Recorded clockUTC and effective fill time kept distinct; recorded sequence is authoritative visibility order, not market availability. Offset/zone inconsistency and nonexistent DST times reject; offset resolves ambiguous fold. After-expiration-date warning does not infer verified settlement/expiry time.

## Durability, isolation and security limits
- Before SQL: explicit directory, no symlink components, single-link file, stored creation device/inode and marker/ledger UUID/schema hash/version checks. No arbitrary DB picker or research-store access. Wrong header/version/corruption fail without reinitialize. URI mode=rw for existing writable access prevents create-on-Open; RO diagnostics never escalate automatically.
- This is a trusted local, cooperative file boundary, NOT a filesystem sandbox or defense against a file-owner/OS attacker swapping paths between checks or editing both data/hashes/marker. Private directory mode700 on POSIX; Windows inherited ACLs are NOT independently verified or hardened. Local filesystem only; network/cloud-sync paths unsupported operationally and not universally detectable. These are remaining real-use gates, not waived guarantees.
- SQL values parameterized; connection authorizer denies ATTACH/DETACH, virtual-table creation and SQL extension/readfile/writefile helpers. No SQL command input surface. Raw private connection/internal code is trusted; do not claim general SQL/filesystem sandboxing. No SDK/order/feed imports. FK/trusted_schema settings explicit; journal DELETE, synchronousFULL, bounded250ms SQLite timeout. Connections close explicitly, including exceptions.
- Initialization commits metadata/schema before writing identity marker. BEGIN IMMEDIATE validates complete proposed correction/lot projection and appends receipt/revisions atomically. Lost acknowledgement retries same UUID; stale predecessor rejects. Process tests cover killed writer pre/post commit and actual cache-spill hot journal. This is not hardware power-loss certification; OS/filesystem/controller durability limits remain.
- Nonzero journal/any WAL/SHM blocks ordinary Open. Recover requires operator's exclusive-ownership confirmation; it does NOT prove no other process is active. Raw capture can only be considered pre-recovery evidence under that assertion, not an online backup. Busy/sidecar states surface errors; no unbounded retry. Incomplete backup/export has no completion identity/manifest. Restore only into new path. No migration API, automatic orphan cleanup or raw journal deletion.
- SQLite/JSON/CSV/backups are plaintext; hashes are not encryption, signatures, broker proof or protection against owner tampering. No real records in this draft. No account secrets, telemetry, retention deletion or production data imported. Independent review was waived only for development/testing; internal review remains explicitly non-independent. No merge, deployment or real-record authorization.
